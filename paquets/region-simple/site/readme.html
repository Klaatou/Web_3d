Région clé en main : documentationTurnkey region: documentation

Ce paquet ouvre votre région (un fichier GLB) dans un navigateur, sans rien installer pour la visiter. Le nom de la région est region : mettez votre GLB sous le nom region.glb, ou renommez la région (section 9).

Les documents complets sont dans le dépôt : https://github.com/Klaatou/Web_3d (docs/fr/PROCEDURES.md, docs/fr/MANUEL.md). Ce fichier n'en reprend que l'essentiel.

1. Où se trouve quoi

  • site/region.glb : votre région. Ici, un petit exemple (sol, maison, deux arbres) : remplacez-le par le vôtre.
  • site/region.config.json : les réglages (section 6).
  • site/region.zones.json : les zones (portails, panneaux, images). Ici une seule : le petit panneau « ? » posé sur le mur est de la maison d'exemple, qui ouvre aide.html. À revoir quand vous installez votre propre GLB : ce panneau est posé sur la maison de l'exemple. Pour le supprimer, ouvrez region.zones.json avec le Bloc-notes et remplacez tout son contenu par [] ; pour le déplacer, voir la section 8.
  • site/aide.html : l'aide des visiteurs, ouverte par ce panneau. Elle commence par un cadre qui renvoie vers ce document : supprimez ce cadre, puis adaptez la page à votre région.
  • site/readme.html : ce document, pour le créateur. Vous pouvez le retirer de site avant de publier.
  • site/medias/aide.jpg : l'image du panneau d'aide.
  • site/default.json : dit quelle région ouvrir. Il contient {"region": "region"}.
  • site/index.html, site/lib/ : la page et sa bibliothèque 3D : à ne pas modifier.
  • lancer-region.bat : montre la région sur cet ordinateur. renommer-region.bat : change le nom de la région. Les mêmes pour Linux et macOS : lancer-region.sh, renommer-region.sh et les fichiers .command (voir la section 3).
  • presence/ : le serveur de présence, facultatif (section 4).

2. Obtenir un GLB depuis un OAR

  1. Il faut Windows, Python 3.9 ou plus, et convoar.exe (l'outil qui convertit un OAR en fichiers 3D ; oar2glb.py le lance pour vous). Téléchargement de convoar : https://github.com/Misterblue/convoar/tree/master/bin.
  2. oar2glb.py est dans le dossier dist du dépôt Web_3d (https://github.com/Klaatou/Web_3d/tree/main/dist). Dans une fenêtre de commandes : python oar2glb.py "C:\chemin\MaRegion.oar". Le GLB est écrit à côté de l'OAR (MaRegion.glb).
  3. Copiez-le dans site\ sous le nom region.glb, puis rechargez la page.
  4. Ce paquet convient aux régions « légères » : en gros, un GLB de moins de 150 Mo et de 3 millions de triangles. python glb2tiles.py MaRegion.glb --analyse le vérifie sans rien écrire. Au-delà, il faut découper la région en tuiles : docs/fr/PROCEDURES.md § 2, hors de ce paquet.

Détails : docs/fr/PROCEDURES.md § 1.

3. Montrer la région

  • Chez vous, ou sur une clé USB : sous Windows, double-cliquez sur lancer-region.bat ; sous macOS, sur lancer-region.command (la première fois : clic droit, Ouvrir) ; sous Linux (ou macOS dans le Terminal), tapez sh lancer-region.sh dans un terminal ouvert dans ce dossier (Python 3.7 ou plus). Laissez ouverte la fenêtre noire ou le terminal, qui affiche « Region sur http://localhost:8000/ … » (le numéro peut être un autre que 8000 si 8000 est pris) : la fermer, ou taper Ctrl+C sous Linux et macOS, arrête le serveur. Seul votre ordinateur voit la région. Double-cliquer sur index.html ne marche pas. Les lanceurs macOS n'ont pas encore été essayés sur un Mac.
  • Autre système : dans le dossier site, python -m http.server puis http://localhost:8000/ (8000 est le port par défaut).
  • Sur un site web : copiez le contenu du dossier site, et rien d'autre, sur votre hébergement. Rien à installer sur le serveur. Gardez les noms de fichiers en minuscules.

4. Présence : voir les autres visiteurs et tchatter (facultatif)

Par défaut chaque visiteur est seul. Le serveur de présence est fourni dans presence/ (copie de presence_server.py du dépôt Web_3d, dossier dist, licence MIT).

  1. Installez Python (python.org), puis : pip install websockets
  2. Dans le dossier presence, lancez : python presence_server.py
  3. Dans site/region.config.json : "presenceUrl": "ws://*:8765" et "chat": true. Le * veut dire « la même machine que la page ».
  4. Servez la région avec python -m http.server lancé dans le dossier site (pas avec lancer-region.bat, réservé à votre ordinateur).
  5. Donnez à vos visiteurs http://ADRESSE:8000/. Pour des proches sur votre réseau, ADRESSE est l'adresse IP de votre PC (commande ipconfig). Pour des visiteurs sur Internet, c'est votre adresse IP publique ou un nom de domaine, après avoir ouvert les ports 8000 et 8765 de votre box vers votre PC.

Un visiteur apparaît dans la présence quand il entre en promenade (touche P ou F). Pour Internet, attention : cela expose votre ordinateur, qui doit rester allumé, et votre adresse IP peut changer. Si la région est sur un hébergement en https, la présence doit être en wss://, avec un certificat : docs/fr/PROCEDURES.md § 6.

Données personnelles. Pseudos, messages et adresses IP des visiteurs sont des données personnelles : prévenez vos visiteurs. Réglages de conservation : options --log-days, --log-ip, --history-days du serveur (docs/fr/MANUEL.md § 18.6, 18.7 et 22.6, docs/fr/PROCEDURES.md § 6). Le serveur écrit ses fichiers dans le dossier presence : ne les copiez jamais dans site.

5. Quand ça ne marche pas

  • « Aucune région à ouvrir » : default.json doit contenir le bon nom, et NOM.config.json doit exister dans site avec ce nom exact.
  • La page ne s'ouvre pas en double-cliquant sur index.html : normal, passez par lancer-region.bat ou un hébergement.
  • « présence interrompue » : presenceUrl est rempli mais aucun serveur de présence ne répond. Videz presenceUrl, ou lancez le serveur.
  • Une image ou une zone n'apparaît pas sur un hébergement : vérifiez les majuscules (2.jpg n'est pas 2.JPG).
  • Plus d'aide : docs/fr/PROCEDURES.md § 9 dans le dépôt Web_3d.

6. Les réglages de region.config.json

Ouvrez le fichier avec le Bloc-notes, changez une valeur, enregistrez, puis rechargez la page (F5) : elle relit le fichier à chaque ouverture. Le JSON est strict : gardez les guillemets et les virgules. Les couleurs sont des nombres décimaux, pas des codes hexadécimaux.

Vue de départ

Clé Valeur dans le modèle Rôle
target [0, 15, 0] cible de la caméra au départ, [x, y, z] (avec targetExplicit à true, la page garde ce cadrage)
camDir [-0.55, 0.42, 0.72] direction de la caméra, [x, y, z]
zoom 0.65 ratio de cadrage (1 = cadrage automatique)

Mer et ciel

Clé Valeur dans le modèle Rôle
sea true afficher la mer (true) ou non (false)
seaY 10 hauteur de la mer, de -150 à 60
seaColor 3840729 couleur de la mer (nombre décimal : 3840729 = 3a9ad9)
skyColor 8900331 couleur du ciel (nombre décimal)
wave 0.5 amplitude des vagues, de 0 à 10
hole 180 rayon du trou de la mer, de 30 à 600 (zone plate = rayon moins fondu)
holeFade 60 demi-largeur du fondu du trou

Promenade

Clé Valeur dans le modèle Rôle
walk true mode promenade (touches P ou F)
fly true vol en promenade (touche F ou Début ; Page Haut ou E monte, Page Bas ou C descend)
eyeHeight 1.7 hauteur des yeux en mètres
walkSpeed 3.5 vitesse de marche en m/s (Maj = x2,2)
walkIgnore "door, porte" objets qu'on traverse, séparés par des virgules : door = tout nom qui commence par ce mot, =mesh_346_5 = ce nom exact, "" = aucun
solidMaterials null matériaux rendus opaques (ils masquent ce qui est derrière), séparés par des virgules : 1471516 = tout nom qui contient ce texte, =pbrmat-123 = nom exact
foliageCutout 0.12 seuil de transparence des feuillages, de 0 à 0.5

Orientation

Clé Valeur dans le modèle Rôle
rotate 0 rotation de la région : 0, 90, 180 ou 270 degrés
northDeg 0.0 décalage en degrés ajouté au cap affiché ; 0 = le nord est la direction -Z du modèle (OpenSim)
compass true boussole en haut de la page

Affichage

Clé Valeur dans le modèle Rôle
panel true panneau de réglages pour les visiteurs (bouton en haut à droite)
retina false haute résolution par défaut (plus net, environ 4 fois plus lourd)
light false la page s'ouvre en rendu léger tant que le visiteur n'a rien choisi

Présence (facultatif)

Clé Valeur dans le modèle Rôle
presenceUrl "" adresse du serveur de présence : ws://... ou wss://... ; * à la place du nom = la même machine que la page ; vide = désactivé
chat false chat entre visiteurs (demande presenceUrl)
spectate false voir les visiteurs depuis la vue globale (se connecte dès l'ouverture)
room "region" nom du salon de présence (le script de renommage le met à jour)

Pour changer plusieurs valeurs d'un coup sans éditer le fichier, glb2html.py --update (dossier dist du dépôt) s'en charge : docs/fr/PROCEDURES.md § 3. Toutes les clés sont décrites dans le dépôt (REFERENCE_OPTIONS.md).

7. Régler la vue de départ

Changez target, camDir et zoom dans region.config.json par petits essais, en rechargeant la page (F5) à chaque fois. Le point target est la position, en mètres, vers laquelle la caméra regarde ; camDir indique d'où elle regarde.

8. Poser, déplacer ou supprimer des zones (portails, panneaux, images)

Les zones se posent dans le viewer du dépôt, glb-viewer.html (dossier dist, https://github.com/Klaatou/Web_3d/tree/main/dist) : ouvrez-le, chargez votre GLB (« Ouvrir .glb »), puis « Importer zones (.json) » avec site/region.zones.json pour reprendre les zones existantes. Posez, déplacez ou supprimez les zones, cliquez sur « Exporter zones (.json) » et copiez le fichier dans site\ sous le nom region.zones.json. Procédure : docs/fr/PROCEDURES.md § 5 et docs/fr/MANUEL.md §§ 3 à 12.

Le panneau d'aide de l'exemple. Avec votre propre GLB, il flotte dans le vide : à vous de le supprimer ou de le replacer. - Supprimer : remplacez tout le contenu de region.zones.json par []. - Déplacer : dans le viewer, importez region.zones.json, ouvrez la zone « Aide » dans la liste et réglez sa position ; ou supprimez-la et posez-en une nouvelle (type Image, image aide.jpg, lien aide.html) par un clic sur un mur. - À la main, dans region.zones.json : x, y, z (la position) et yaw (l'orientation, en radians). Attention : ce sont les coordonnées de la page, qui recentre le modèle : elles ne sont pas celles du fichier GLB. Le plus simple est de relever la position dans la page (touche I, ligne « Position avatar » : x, y, z et yaw).

Un panneau « Lien vers OpenSim » (lien hop://) à personnaliser. Le paquet contient un panneau d'exemple, la zone zhop : l'image site/medias/hop.jpg (« Lien vers OpenSim ») et un lien hop:// incomplet. Un clic dessus (ou la touche E devant) ouvre le monde visé dans le viewer OpenSim ou Second Life du visiteur, à condition que son ordinateur ait enregistré le protocole hop:// (voir docs/fr/PROCEDURES.md § 13, dans le dépôt Web_3d). Pour l'adapter :

  1. L'image : remplacez site/medias/hop.jpg par la vôtre (même nom, minuscules). Pour un titre sous l'image, créez site/medias/hop.txt : sa première ligne sera le titre.
  2. La position : visitez la page à pied et placez-vous face à l'endroit voulu, à un mètre environ. En bas de la fenêtre Aide (touche H), choisissez le format « xyz » à côté de « Copier ma position », cliquez sur le bouton, puis collez le résultat dans le Bloc-notes : x, y, z, en mètres. Le y relevé est celui du sol. Dans le bloc Informations / État (touche I), la ligne « Position avatar » se termine par le yaw, en radians : c'est l'orientation (le panneau se lit des deux côtés : le sens n'a pas d'importance).
  3. Le fichier : ouvrez site/region.zones.json avec le Bloc-notes, trouvez le bloc "id": "zhop" et changez : x et z (ceux relevés) ; y = le sol relevé + la hauteur du centre du tableau (par exemple 1.5 : un sol à 15.0 donne 16.5, avec un point) ; yaw (celui lu dans Informations / État) ; target : le nom de l'image (hop.jpg) ; link : l'adresse hop:// du monde visé (hop://ADRESSE:8002/Region est un exemple : remplacez ADRESSE, le port et le nom de la région). Facultatif : w, la largeur en mètres (avec h à 0, la hauteur suit l'image) et label, le nom de la zone.
  4. Enregistrez le fichier et rechargez la page (F5) : le panneau apparaît à l'endroit relevé. Pour un deuxième panneau, copiez tout le bloc de la zone (accolades comprises), séparez-le du précédent par une virgule, puis changez son id, son image et son link.

9. Renommer la région

Pourquoi. Pour donner à votre région le nom de votre choix (par exemple MonIle) au lieu de region. Ce nom devient aussi celui du salon de présence : les visiteurs d'une région ne voient que ceux de la même.

Comment. 1. Si le lanceur est ouvert, fermez sa fenêtre noire. 2. Double-cliquez sur renommer-region.bat. Une fenêtre demande « Nouveau nom (lettres, chiffres, tiret, souligné) » : tapez MonIle, puis Entrée. (Ou, dans une fenêtre de commandes ouverte dans ce dossier : renommer-region.bat MonIle. Sous macOS : renommer-region.command. Sous Linux : sh renommer-region.sh MonIle.) 3. La fenêtre liste ce qu'elle a fait. Rechargez la page (F5).

Ce que le script change (et rien d'autre) :

Avant Après
site\region.glb site\MonIle.glb
site\region.config.json site\MonIle.config.json
site\region.zones.json site\MonIle.zones.json
site\default.json : {{"region": "region"}} {{"region": "MonIle"}}
dans MonIle.config.json : "room": "region" "room": "MonIle"
dans site\regions.json : "id", "room" et l'adresse (region=region) le nouveau nom à la place de l'ancien

À savoir. - Le nom ne peut contenir que des lettres, des chiffres, - et _ (ni espace, ni point). Évitez les accents. - Si un fichier du nouveau nom existe déjà dans site, le script s'arrête sans rien modifier. - Votre GLB, s'il est déjà dans site sous le nom region.glb, est renommé avec le reste. Un GLB que vous ajouterez plus tard doit porter le nouveau nom : MonIle.glb. - Pour revenir au nom d'origine, relancez le script avec region. - À la main, ce sont exactement ces cinq changements. La page elle-même (index.html) n'est jamais modifiée.

10. Figurer sur une carte des mondes (facultatif)

Votre paquet a déjà sa propre carte. Ouvrez carte.html (par exemple http://localhost:8000/carte.html) : elle affiche votre région sous forme d'une tuile cliquable, avec sa vignette. Même avec une seule région, c'est une page de présentation : mettez-la en ligne avec le reste du dossier site et donnez son adresse, ou faites-y un lien depuis votre propre page de présentation. Deux fichiers la règlent :

  • site\regions.json : la fiche (name : le nom affiché, 60 caractères au plus ; x et y : la place sur la grille ; thumb : la vignette). Pour présenter d'autres régions, ajoutez d'autres fiches de la même forme.
  • site\vignette.jpg : l'image de la tuile. Remplacez-la par une capture de votre région : carrée, 320 x 320 pixels, JPEG, quelques dizaines de Ko. Le viewer sait en fabriquer une (section « Carte des mondes », bouton « Capturer la vignette »).

Le script de renommage (section 9) tient cette carte à jour. Ce qui suit concerne une carte commune à plusieurs créateurs, tenue par quelqu'un d'autre.

Une carte des mondes est une page (carte.html) qui présente plusieurs régions sous forme de tuiles cliquables. Si quelqu'un tient une carte commune à plusieurs créateurs, voici ce qu'il faut lui transmettre pour que votre région y figure :

Information Exemple Remarque
nom affiché Mon île 60 caractères au plus
adresse de la page https://monsite.exemple/index.html complète (https://…) : une adresse relative ne marcherait pas depuis une autre carte
vignette une image jpg, png ou webp de 140 Ko au plus, ou son adresse https://monsite.exemple/vignette.jpg une capture de votre région vue de dessus ou à hauteur d'yeux
place sur la grille (facultatif) 1000,1001 comme dans OpenSim : x vers l'est, y vers le nord
présence (facultatif) wss://… et le nom du salon (la clé room de region.config.json) pour que la carte compte les visiteurs ; si votre serveur de présence limite les origines (option --origins), ajoutez-y l'adresse de la carte

Tout cela tient en une fiche de quelques lignes (format regions.json, manuel § 11.6) :

{"id": "MonIle", "name": "Mon île", "url": "https://monsite.exemple/index.html", "x": 1000, "y": 1001, "thumb": "https://monsite.exemple/vignette.jpg"}

Pour que votre page ait elle aussi le bouton « Carte (M) », renseignez la clé mapUrl de region.config.json avec l'adresse du regions.json de la carte (une carte hébergée ailleurs doit autoriser sa lecture depuis votre site). Rien de tout cela n'est nécessaire pour une région seule.

This package opens your region (a GLB file) in a browser, with nothing to install to visit it. The region's name is region: put your GLB under the name region.glb, or rename the region (section 9).

The full documents are in the repository: https://github.com/Klaatou/Web_3d (docs/en/PROCEDURES.md, docs/en/MANUAL.md). This file only repeats the essentials.

1. What is where

  • site/region.glb: your region. Here, a tiny example (ground, house, two trees): replace it with yours.
  • site/region.config.json: the settings (section 6).
  • site/region.zones.json: the zones (portals, signs, pictures). Just one here: the small "?" panel on the east wall of the example house, which opens aide.html. To review when you install your own GLB: that panel sits on the example's house. To delete it, open region.zones.json with Notepad and replace all its contents with []; to move it, see section 8.
  • site/aide.html: the visitors' help, opened by that panel. It starts with a box pointing to this document: delete that box, then adapt the page to your region.
  • site/readme.html: this document, for the creator. You may remove it from site before publishing.
  • site/medias/aide.jpg: the help panel's image.
  • site/default.json: says which region to open. It contains {"region": "region"}.
  • site/index.html, site/lib/: the page and its 3D library: do not edit.
  • lancer-region.bat: shows the region on this computer. renommer-region.bat: changes the region's name. The same for Linux and macOS: lancer-region.sh, renommer-region.sh and the .command files (see section 3).
  • presence/: the presence server, optional (section 4).

2. Getting a GLB from an OAR

  1. You need Windows, Python 3.9 or later, and convoar.exe (the tool that converts an OAR into 3D files; oar2glb.py runs it for you). Download convoar: https://github.com/Misterblue/convoar/tree/master/bin.
  2. oar2glb.py is in the Web_3d repository's dist folder (https://github.com/Klaatou/Web_3d/tree/main/dist). In a command window: python oar2glb.py "C:\path\MyRegion.oar". The GLB is written next to the OAR (MyRegion.glb).
  3. Copy it into site\ under the name region.glb, then reload the page.
  4. This package suits "light" regions: roughly a GLB under 150 MB and 3 million triangles. python glb2tiles.py MyRegion.glb --analyse checks it without writing anything. Beyond that the region must be split into tiles: docs/en/PROCEDURES.md § 2, outside this package.

Details: docs/en/PROCEDURES.md § 1.

3. Showing the region

  • At home, or on a USB stick: on Windows, double-click lancer-region.bat; on macOS, lancer-region.command (the first time: right-click, Open); on Linux (or macOS in the Terminal), type sh lancer-region.sh in a terminal opened in this folder (Python 3.7 or later). Keep open the black window or the terminal, which shows "Region sur http://localhost:8000/ …" (the number may differ from 8000 if 8000 is taken): closing it, or pressing Ctrl+C on Linux and macOS, stops the server. Only your computer sees the region. Double-clicking index.html does not work. The macOS launchers have not been tried on a Mac yet.
  • Other systems: in the site folder, python -m http.server then http://localhost:8000/ (8000 is the default port).
  • On a website: copy the contents of the site folder, and nothing else, to your hosting. Nothing to install on the server. Keep file names in lowercase.

4. Presence: seeing the other visitors and chatting (optional)

By default every visitor is alone. The presence server is supplied in presence/ (a copy of presence_server.py from the Web_3d repository, dist folder, MIT licence).

  1. Install Python (python.org), then: pip install websockets
  2. In the presence folder, run: python presence_server.py
  3. In site/region.config.json: "presenceUrl": "ws://*:8765" and "chat": true. The * means "the same machine as the page".
  4. Serve the region with python -m http.server run in the site folder (not with lancer-region.bat, which is only for your own computer).
  5. Give your visitors http://ADDRESS:8000/. For people on your own network, ADDRESS is your PC's IP address (the ipconfig command). For visitors on the Internet, it is your public IP address or a domain name, after opening ports 8000 and 8765 on your router towards your PC.

A visitor appears in the presence when they start walking (P or F key). For the Internet, be careful: this exposes your computer, which must stay on, and your IP address may change. If the region is on an https host, the presence must be wss://, with a certificate: docs/en/PROCEDURES.md § 6.

Personal data. Visitors' nicknames, chat messages and IP addresses are personal data: tell your visitors. Retention settings: the server's --log-days, --log-ip, --history-days options (docs/en/MANUAL.md § 18.6, 18.7 and 22.6, docs/en/PROCEDURES.md § 6). The server writes its files in the presence folder: never copy them into site.

5. When it does not work

  • "No region to open": default.json must contain the right name, and NAME.config.json must exist in site with that exact name.
  • The page does not open by double-clicking index.html: expected, use lancer-region.bat or a web host.
  • "presence interrupted": presenceUrl is filled in but no presence server answers. Empty presenceUrl, or start the server.
  • A picture or zone does not show on a host: check capital letters (2.jpg is not 2.JPG).
  • More help: docs/en/PROCEDURES.md § 9 in the Web_3d repository.

6. The settings in region.config.json

Open the file with Notepad, change a value, save, then reload the page (F5): it re-reads the file at every opening. The JSON is strict: keep the quotes and commas. Colours are decimal numbers, not hexadecimal codes.

Starting view

Key Value in the template Role
target [0, 15, 0] camera target at start, [x, y, z] (with targetExplicit set to true, the page keeps this framing)
camDir [-0.55, 0.42, 0.72] camera direction, [x, y, z]
zoom 0.65 framing ratio (1 = automatic framing)

Sea and sky

Key Value in the template Role
sea true show the sea (true) or not (false)
seaY 10 sea height, from -150 to 60
seaColor 3840729 sea colour (decimal number: 3840729 = 3a9ad9)
skyColor 8900331 sky colour (decimal number)
wave 0.5 wave amplitude, 0 to 10
hole 180 radius of the hole in the sea, 30 to 600 (flat zone = radius minus fade)
holeFade 60 half-width of the hole's fade

Walking

Key Value in the template Role
walk true walking mode (P or F key)
fly true flying while walking (F or Home key; Page Up or E goes up, Page Down or C goes down)
eyeHeight 1.7 eye height in metres
walkSpeed 3.5 walking speed in m/s (Shift = x2.2)
walkIgnore "door, porte" objects you walk through, comma-separated: door = any name starting with that word, =mesh_346_5 = that exact name, "" = none
solidMaterials null materials drawn opaque (they hide what is behind), comma-separated: 1471516 = any name containing that text, =pbrmat-123 = exact name
foliageCutout 0.12 foliage transparency threshold, 0 to 0.5

Orientation

Key Value in the template Role
rotate 0 region rotation: 0, 90, 180 or 270 degrees
northDeg 0.0 offset in degrees added to the displayed heading; 0 = north is the model's -Z direction (OpenSim)
compass true compass at the top of the page

Display

Key Value in the template Role
panel true settings panel for visitors (button at the top right)
retina false high resolution by default (sharper, about 4 times heavier)
light false the page opens in light rendering until the visitor has chosen something

Presence (optional)

Key Value in the template Role
presenceUrl "" presence server address: ws://... or wss://...; * instead of the name = the same machine as the page; empty = off
chat false chat between visitors (needs presenceUrl)
spectate false see visitors from the global view (connects as soon as the page opens)
room "region" presence room name (the renaming script updates it)

To change several values at once without editing the file, glb2html.py --update (the repository's dist folder) does it: docs/en/PROCEDURES.md § 3. All keys are described in the repository (REFERENCE_OPTIONS.md).

7. Setting the starting view

Change target, camDir and zoom in region.config.json by small trials, reloading the page (F5) each time. target is the position, in metres, the camera looks at; camDir says where it looks from.

8. Placing, moving or deleting zones (portals, signs, pictures)

Zones are placed in the repository's viewer, glb-viewer.html (the dist folder, https://github.com/Klaatou/Web_3d/tree/main/dist): open it, load your GLB ("Open .glb"), then "Import zones (.json)" with site/region.zones.json to bring in the existing zones. Place, move or delete zones, click "Export zones (.json)" and copy the file into site\ under the name region.zones.json. Procedure: docs/en/PROCEDURES.md § 5 and docs/en/MANUAL.md §§ 3 to 12.

The example's help panel. With your own GLB it floats in empty space: you have to delete it or put it back somewhere. - Delete: replace all the contents of region.zones.json with []. - Move: in the viewer, import region.zones.json, open the "Aide" zone in the list and set its position; or delete it and place a new one (Image type, image aide.jpg, link aide.html) by clicking a wall. - By hand, in region.zones.json: x, y, z (the position) and yaw (the orientation, in radians). Careful: these are the page's coordinates, and the page recentres the model: they are not those of the GLB file. The simplest is to read the position in the page (the I key, "Position avatar" line: x, y, z and yaw).

A “Lien vers OpenSim” panel (hop:// link) to customise. The package contains an example panel, the zhop zone: the image site/medias/hop.jpg (“Lien vers OpenSim”, French for “link to OpenSim”) and an incomplete hop:// link. Clicking it (or pressing E in front of it) opens the target world in the visitor's OpenSim or Second Life viewer, provided the visitor's computer has registered the hop:// protocol (see docs/en/PROCEDURES.md § 13, in the Web_3d repository). To adapt it:

  1. The image: replace site/medias/hop.jpg with yours (same name, lowercase). For a title under the image, create site/medias/hop.txt: its first line will be the title.
  2. The position: visit the page on foot and stand facing the spot you want, about one metre away. At the bottom of the Help window (H key), choose the “xyz” format next to “Copy my position”, click the button, then paste the result into Notepad: x, y, z, in metres. The y you get is the floor. In the Information / Status block (I key), the “Position avatar” line ends with the yaw, in radians: it is the orientation (the panel reads on both sides: the direction does not matter).
  3. The file: open site/region.zones.json with Notepad, find the "id": "zhop" block and change: x and z (the ones you got); y = the floor you got + the height of the picture's centre (for example 1.5: a floor at 15.0 gives 16.5, with a dot); yaw (the one read in Information / Status); target: the image name (hop.jpg); link: the hop:// address of the target world (hop://ADRESSE:8002/Region is an example: replace ADRESSE, the port and the region name). Optional: w, the width in metres (with h at 0 the height follows the image) and label, the zone name.
  4. Save the file and reload the page (F5): the panel appears at the spot you noted. For a second panel, copy the whole zone block (braces included), separate it from the previous one with a comma, then change its id, its image and its link.

9. Renaming the region

Why. To give your region the name you want (for example MyIsland) instead of region. This name is also the presence room: visitors of one region only see those of the same one.

How. 1. If the launcher is open, close its black window. 2. Double-click renommer-region.bat. A window asks "Nouveau nom (lettres, chiffres, tiret, souligne)" (new name): type MyIsland, then Enter. (Or, in a command window opened in this folder: renommer-region.bat MyIsland. On macOS: renommer-region.command. On Linux: sh renommer-region.sh MyIsland.) 3. The window lists what it did. Reload the page (F5).

What the script changes (and nothing else):

Before After
site\region.glb site\MyIsland.glb
site\region.config.json site\MyIsland.config.json
site\region.zones.json site\MyIsland.zones.json
site\default.json: {{"region": "region"}} {{"region": "MyIsland"}}
in MyIsland.config.json: "room": "region" "room": "MyIsland"
in site\regions.json: "id", "room" and the address (region=region) the new name instead of the old one

Good to know. - The name may only contain letters, digits, - and _ (no space, no dot). Avoid accents. - If a file with the new name already exists in site, the script stops without changing anything. - Your GLB, if it is already in site as region.glb, is renamed with the rest. A GLB you add later must carry the new name: MyIsland.glb. - To go back to the original name, run the script again with region. - By hand, these are exactly the five changes. The page itself (index.html) is never modified.

10. Appearing on a world map (optional)

Your package already has its own map. Open carte.html (for example http://localhost:8000/carte.html): it shows your region as a clickable tile, with its thumbnail. Even with a single region, it is a presentation page: put it online with the rest of the site folder and give its address, or link to it from your own presentation page. Two files set it:

  • site\regions.json: the card (name: the displayed name, 60 characters at most; x and y: the place on the grid; thumb: the thumbnail). To present other regions, add other cards of the same form.
  • site\vignette.jpg: the tile's image. Replace it with a capture of your region: square, 320 x 320 pixels, JPEG, a few tens of KB. The viewer can make one (section "World map", button "Capture the thumbnail").

The renaming script (section 9) keeps this map up to date. What follows is about a map shared by several creators, kept by someone else.

A world map is a page (carte.html) that shows several regions as clickable tiles. If someone keeps a map shared by several creators, here is what to send them so that your region appears on it:

Information Example Note
displayed name My island 60 characters at most
page address https://mysite.example/index.html complete (https://…): a relative address would not work from another map
thumbnail a jpg, png or webp image of 140 KB at most, or its address https://mysite.example/thumbnail.jpg a picture of your region seen from above or at eye level
place on the grid (optional) 1000,1001 as in OpenSim: x towards the east, y towards the north
presence (optional) wss://… and the room name (the room key of region.config.json) so that the map counts the visitors; if your presence server limits origins (the --origins option), add the map's address to it

All of this fits in a card of a few lines (regions.json format, manual § 11.6):

{"id": "MyIsland", "name": "My island", "url": "https://mysite.example/index.html", "x": 1000, "y": 1001, "thumb": "https://mysite.example/thumbnail.jpg"}

For your page to have the "Map (M)" button too, set the mapUrl key of region.config.json to the address of the map's regions.json (a map hosted elsewhere must allow it to be read from your site). None of this is needed for a region single one.
