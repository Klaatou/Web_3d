## Architecture
- `src/core.js` : noyau JS partagé (collisions, promenade, avatars, zones, carte, chat). Inséré dans `template.html` ET dans `viewer_tpl.html`.
- `src/template.html` : page exportée (placeholders `__IMPORTMAP__`, `__CONFIG__`, `__GLB_B64__`, `__DECODERS__`, `__TITLE__`, `__SKY_HEX__`, `__CORE__`).
- `src/viewer_tpl.html` : page de réglages/export ; embarque le template et le script Python pour pouvoir exporter et fournir la ligne de commande.
- `src/gen_tpl.py` : script de génération (devient `dist/glb2html.py`). Points d'entrée : `build_html` (cfg + page), `generate`, `build_shell` (coquille modulaire universelle), `main` (arguments ; `--settings` relit le fichier en deux passes d'argparse), `clean_map` / `clean_zones` (assainissement), `register_region`, `write_map_page` (+ `MAP_PAGE_TEMPLATE`), `settings_defaults`. Mode tuiles (v30) : `generate_tiles`, `place_tiles`, `read_tiles_index`, `safe_rel_path`.
- `tools/glb2tiles.py` (+ `tools/glb-stats.py` à côté) : découpe un GLB énorme en tuiles autonomes, remplace les images invalides par un gris, écrit la vue d'ensemble `X.overview.glb` (v31) et les références d'objets (v32). Un seul fichier ; `build.py` en fabrique `dist/glb2tiles.py`.
- `src/presence_server.py` : serveur WebSocket (bibliothèque `websockets`).
- `build.py` : assemble le tout dans `dist/`. **Ne jamais éditer `dist/`** : modifier `src/` puis `python build.py`. Le texte de la coquille modulaire n'est écrit qu'une fois, dans `gen_tpl.py` (`build_shell`) : `build.py` charge le script fabriqué et en tire la coquille pour le viewer (export `.zip`), sans la recopier.
- Contraintes de fabrication : les textes insérés dans des chaînes Python `r"""..."""` ne doivent contenir ni `"""` ni finir par `\` (build.py le vérifie). `__VERSION__` est remplacé partout, y compris dans `MAP_PAGE_TEMPLATE`.
- Les clés de `cfg` doivent rester identiques entre l'export du viewer (JS) et celui du script (Python).
- Version : fichier `VERSION` + `CHANGELOG.md` à chaque livraison.

## Décisions techniques acquises
- Page exportée 100 % autonome par défaut : three.js r160, GLTFLoader, OrbitControls, Draco et Meshopt en `data:` dans l'importmap ; GLB en base64. Aucun réseau à l'ouverture, ouverture possible depuis le disque.
- `0.0.0.0` n'est pas une adresse de connexion : `ws://0.0.0.0:p` devient `ws://127.0.0.1:p` (script et viewer).
- Pas de collisions entre visiteurs (positions côté client).
- Zones en JSON séparé (pas dans le GLB). `zones.json` cherché dans le dossier de lancement puis dans celui du script (idem `regions.json`). `--zones-live` recharge les zones à chaque ouverture (http seulement).
- Haute résolution = supersampling ×2 minimum. Mer : 400 segments par défaut (maille 10 m) pour que le trou soit net.
- Collision : `door` = début de mot ; `=mesh_346_5` = nom exact.
- Carte : X est / Y nord (style OpenSim), pas de borne ; placement compact (un vide de plus de 2 cases compte pour 2 ; liste simple si coordonnées en double ou plus de 14 colonnes/lignes).
- Réglages mémorisés par fichier (clé nom+taille du `.glb`) dans le navigateur ; export/import `.reglages.json`, relu par `glb2html.py --settings`.
- Sécurité : les adresses de carte/zones sont filtrées (http/https), vignettes = data:image ou lien, tailles bornées. Le profil `public` retire les zones privées (Home Assistant).

## Décisions de la v26 (21/10/2026) : coquille unique
- Une seule coquille (par défaut `index.html`) et un seul `lib/` pour plusieurs régions d'un dossier ; par région : `X.glb`, `X.config.json`, `X.zones.json`. Adresse `COQUILLE.html?region=NOM`. La coquille reste identique octet pour octet et lit `?region=` à l'exécution (aucun nom écrit dedans) ; sans `region`, comportement d'avant (fichiers déduits du nom de la page).
- **Sécurité, non négociable** : NOM = un seul nom de fichier ; refusé (message dans la page, aucune requête réseau) s'il est vide, contient `/` `\` `:` `?` `#` `..` ou un caractère de contrôle, ou commence par un point (après retrait de `.html`). La règle existe deux fois, à garder identique : JS dans `SHELL_BOOT_NEW` et `valid_region_name` (gen_tpl.py) ; le viewer la reprend pour son `.zip`. Ne jamais accepter une adresse dans `region` (portails piégés, webhooks Home Assistant envoyés ailleurs).
- `glb2html.py --shared-shell [COQUILLE.html]` (implique `--modular`) : `-o` désigne la région, `X.html` n'est pas écrit ; coquille et `lib/` écrits seulement s'ils sont absents, une coquille existante et différente n'est jamais écrasée (avertissement). `--register` écrit `COQUILLE.html?region=NOM` (`page_name_of`, `shell_page_address`).
- Le `.zip` du viewer contient `index.html` (et non plus `NOM.html`).
- `tools/oar2glb.py` porte `__VERSION__` ; `build.py` en fabrique `dist/oar2glb.py`. `--version` sort avant l'ouverture du journal et avant la pause « Entrée ».

## Décisions de la v28 (21/10/2026) : `tools/glb2tiles.py`
- **Tuiles autonomes** : une tuile = un GLB valide qui s'ouvre seul ; les meshes partagés entre tuiles sont dupliqués dans chaque tuile qui les utilise (une bibliothèque commune serait trop lourde : 525 à 560 Mo pour la 4X4). Ce lot n'écrit que les tuiles et `X.tiles.json` ; ni `src/core.js`, ni `template.html`, ni `viewer_tpl.html` ne sont touchés.
- **Budget en Mo ET en triangles** (`--budget 32`, `--budget-tri 1500000`) : le poids seul ne suffit pas (Aestia : jusqu'à 5,1 M de triangles dans un seul bloc de 64 m). Poids autonome = octets compactés des primitives distinctes + images distinctes.
- **Règle des objets entiers par le poids, pas par l'étendue seule** : un objet racine reste entier si poids autonome ≤ `--entier-poids` (16 Mo) ET étendue ≤ `--entier-etendue` (256 m). L'étendue d'un objet racine ne dit rien de sa taille réelle (« Federalist House » 67 m, 447 meshes ; « Gandalf Statue » 168 m, 27 meshes ; des maisons de 167 m n'ont qu'un mesh) : une règle d'étendue seule couperait des centaines de maisons. Objet avec skin : jamais réparti. Mesh unique plus lourd que le budget (terrain, mer) : avertissement, pas de découpage par triangles à ce stade.
- **Accessors partagés** : des meshes différents partagent souvent un tampon de sommets dont chacun n'utilise qu'une partie ; la somme brute des accessors surestime le poids réel et le champ « sommets rendus » de `glb-stats` est trompeur. glb2tiles compte les sommets réellement indexés (lecture des indices par morceaux) et, quand un mesh n'utilise qu'une partie d'un tampon, lit ses positions pour avoir sa vraie boîte (celle de l'accessor ne convient pas).
- Aucune valeur propre à une région dans le code ; tous les seuils sont des paramètres. Valeurs aberrantes (tatooine2 : prim de 3 097 m) : acceptées, signalées (`--aberrant`).
- `glb-stats.py` : fonctions communes `modele(g)` et `rapport(...)` réutilisées par `glb2tiles.py` (qui l'exige à côté de lui, `build.py` copie les deux dans `dist/`).
- **Mesures des six régions** (avec `glb-stats.py`) : 4X4 « Free House Gallery » 1,2 Go (889 Mo de géométrie, 300 Mo de textures, 30 239 meshes, 60 641 instances, 44,8 M triangles, 1 825 objets racine dont 521 > 64 m et 175 > 128 m, 1 392 x 1 251 m ; blocs de 64 m : 253 non vides, médiane 12 Mo, maximum 78 Mo, 2,1 M triangles au plus ; blocs de 128 m trop lourds : 140 Mo, 3,4 M) ; Aestia 253 Mo (15,8 M triangles, 4,4 M sommets uniques ; blocs de 64 m : médiane 18 Mo, maximum 73 Mo, 5,1 M triangles dans un bloc) ; tatooine2 131 Mo (5,8 M triangles, 944 x 4 005 m, hauteur -3 176 à 3 137 m à cause d'un prim de 3 097 m ; 38 blocs, maximum 50 Mo) ; Club House 50 Mo (2,7 M triangles), Hobbit 28 Mo (0,8 M), Ankh Island 12 Mo (1,5 M) : légères. De 52 à 77 % de la géométrie est utilisée par plusieurs blocs de 64 m (3 % pour Club House).
- Mesuré sur un GLB synthétique de 146 Mo (4 000 instances, 400 meshes) : analyse en 1,7 s pour 40 Mo de mémoire ; découpage en 70 tuiles en 22 s.

## Décisions de la v29 (22/10/2026) : terrain complet, `--exclure`
- **Terrain des régions > 256 m** (`tools/oar2glb.py`) : convoar ne produit qu'un nœud « Terrain » plafonné ; la carte de hauteurs de l'OAR (`terrains/*.r32`, indexation de `terrain_height` : `h[y*n+x]`, 1 échantillon par mètre) donne des patches de `--terrain-patch` m (64), mesh de (P+1)² sommets, bords partagés, nommés « Terrain i,j », objets racine marqués `extras.terrain` (`drop_far` les épargne). Repère X = x, hauteur = h, Z = -y. Normales par différences centrées sur toute la carte. Couleur par sommet `COLOR_0` (sable humide / sable sec / herbe selon l'altitude au-dessus de l'eau, roche au-delà de ~35°), pas d'UV. Niveau d'eau : `WaterHeight` de `settings/*.xml`, sinon 20.
- `--terrain auto|oui|non` : `auto` ne remplace que le nœud « Terrain » de convoar qui couvre moins de 95 % de la carte ; sinon le GLB reste identique octet pour octet (non-régression testée). `--terrain-seul GLB` : réécrit l'en-tête JSON, recopie le chunk binaire par morceaux, ajoute les tampons à la fin ; `X-terrain.glb`, jamais d'écrasement, pas de pause.
- **Pause finale** : `oar2glb.py` et `glb2tiles.py` n'attendent « Entrée » que si stdin est une console (sinon `EOFError`).
- **`glb2tiles.py --exclure`** : décision sur le nom (regex, insensible à la casse), le nombre total de triangles (`--exclure-max-tri`, 24) et le nombre de meshes (`--exclure-max-meshes`, 1) de l'objet racine ; **jamais sur l'étendue** (boîte gonflée par les tampons de sommets partagés). Les exclus sortent du plan (tuiles, poids, triangles, budget).

## Décisions de la v30 (22/10/2026) : la coquille charge les tuiles
- **Activation** par le champ `tiles` de `X.config.json` (chemin relatif de `X.tiles.json`), avec `tileRadius` 150, `tileMargin` 60, `tileMaxMo` 200, `tileMaxTri` 8 000 000, `tileConcurrency` 4. Ces clés ne sont écrites que pour une région en tuiles (la config ordinaire est inchangée) ; elles n'existent que côté script (`glb2html.py --tiles`), le viewer ne charge pas de tuiles et ne les connaît pas. `?rayon=NNN` remplace `tileRadius`.
- **Repère = modèle d'origine, aucun recentrage** (le recentrage du viewer exige tout le modèle). Zones, arrivées, cible, trou de la mer sont dans ce repère ; `rotate` tourne la racine des tuiles autour de l'axe vertical passant par l'origine, valeurs stockées dans le repère déjà tourné (cible par défaut écrite par `--tiles` tournée aussi). Mer centrée sur le centre de l'étendue ; cible et mer par défaut : centre de l'étendue à 20 m, mer à 20 m.
- **Chargement** (`core.js`, section « mode tuiles » de `createViewer`, `viewer.loadTiles`) : distance en plan X,Z à la boîte réelle de la tuile ; charge dans le rayon (plus proches d'abord, `tileConcurrency` à la fois), décharge au-delà de rayon + marge, puis le budget (Mo = poids des fichiers, triangles) en évinçant les tuiles chargées les plus lointaines ; une tuile qui contient le point de référence (distance 0) est chargée même seule hors budget. Point de référence : avatar, sinon cible de la vue globale (arrivée du lien pendant 4 s au démarrage). Échec : nouvelle tentative 3 s, 6 s… 30 s ; `model` = la racine des tuiles (`getter model`), donc picks, atterrissage et double-clic travaillent sur les tuiles chargées.
- **Collisions** : `buildCollisionGrid` est l'enveloppe synchrone du générateur `collisionGridSteps` (même résultat) ; une grille par tuile construite par tranches de 6 ms par image (`tilesTick`, dans la boucle d'animation), grille composite `TG` (`ground`, `wall`, `pending`). **Règle : jamais d'avancée vers un point contenu dans la boîte d'une tuile non prête** (en cours, en échec, grille en construction) ; F, portail interne et double-clic attendent la tuile. Pas de gravité tant que la tuile sous l'avatar n'est pas prête.
- **Zones liées (`mesh`) : ignorées** avec avertissement en v30 (possibles depuis la v32 avec les références d'objets des tuiles). **Limites connues** : pas de vue d'ensemble en v30 (ajoutée en v31 : la vue globale ne montrait que les tuiles chargées), tuiles qui dupliquent les meshes partagés, grille de collision lourde en mémoire (~36 octets par triangle), budget en poids de fichier (les textures décodées pèsent plus).
- **Sécurité** : le chemin `tiles` et chaque `file` de `X.tiles.json` suivent une seule règle, écrite deux fois à garder identique : `safeRel` (JS, `core.js`) et `safe_rel_path` (gen_tpl.py) : relatif, sans `/` initial, sans `\ : ? #` ni caractère de contrôle, sans segment `..` ou vide ; refus sans requête réseau. `?region=` reste un nom de fichier.
- `glb2html.py --tiles X.tiles.json -o X.html [--shared-shell]` : sans `.glb`, ne copie `X.tiles.json` et ses tuiles que s'ils ne sont pas à côté de la page (jamais 1,3 Go pour rien), le dit. La coquille change (chargement des tuiles) : une coquille existante différente n'est pas écrasée.
- `glb2tiles.py` : « octets gagnés » de `--exclure` = octets qu'aucun objet conservé n'utilise ; 0 est normal quand les exclus partagent leurs primitives (cube commun) ; ajout de `bytesShared` et d'une phrase d'explication.

## Décisions de la v31 (22/10/2026) : images invalides, sortie de promenade, vue d'ensemble
- **Images** (`glb2tiles.py`) : une image embarquée de 0 octet, d'un autre format que PNG/JPEG/WebP ou tronquée est remplacée par un PNG gris 4 x 4 (gris 128, comme `oar2glb.py`), un seul par tuile (`image-remplacee`), matériaux et UV inchangés. Mesuré dans Chromium : toute image tronquée échoue au décodage, pas seulement la vide ; la vérification regarde donc la fin (PNG : blocs jusqu'à IEND ; JPEG : FFD9 ; WebP : taille RIFF), par seeks (jamais l'image entière). Compteurs dans `--analyse`, le rapport et `X.tiles.json` (`replacedImages`).
- **Sortie de promenade** (`walkStop`) : la cible de la vue globale passe au sol sous l'avatar, la caméra garde le décalage d'avant l'entrée en promenade (pas de retour à l'ancienne position). En mode tuiles le chargeur suit cette cible. Ne plus jamais restaurer exactement `W.saved.pos` / `W.saved.target`.
- **Vue d'ensemble `X.overview.glb`** : produite par `glb2tiles.py` (aussi `--vue-ensemble-seule`, qui exige les mêmes options de découpage et le vérifie), référencée par la clé `overview` de `X.tiles.json` (`file` = chemin relatif, même règle de sécurité que les tuiles, dans `read_tiles_index` et `loadTiles`). Un nœud par fichier de tuile, **identifié par `extras.tile`** (le GLTFLoader retire `/`, `.` et espaces des noms : ne jamais apparier par `name`). Un matériau, aucune image, couleurs de sommets (`COLOR_0`, linéaires), sans normales (ombrage plat par le chargeur), `doubleSided`. Chaque primitive unique simplifiée une fois (regroupement de sommets, résolution `--ov-resolution` sur sa propre boîte, cache par clé de primitive), recopiée avec la matrice monde de chaque instance ; primitives BLEND et objets à squelette omis ; petits objets omis (`--ov-seuil` 3 m = calcul de taille à l'écran, pas mesure sur la vraie région). Terrain (`extras.terrain`) rééchantillonné sur un réseau commun (cases possédées par la pièce dont [min, max[ contient le coin bas : jamais de fente), au plus la moitié du budget. Budgets 25 Mo / 1,5 M triangles : plus grands objets d'abord, seuil effectif relevé, résolution réduite si l'on omet des objets de plus de `--ov-seuil-max`.
- **Coquille** : vue d'ensemble chargée avant les tuiles ; `ovSync(t)` masque la cellule quand `t.grp` existe et la réaffiche au déchargement (même bloc synchrone que l'ajout / le retrait du groupe). Hors `model` : jamais de collisions, de sol ni de « Chargement du sol… » ; hors budget `tileMaxMo` / `tileMaxTri` ; comptée à part dans la ligne d'information. Seul `setLanding` (double-clic en vue globale) la raye. Cadrage de toute la région, `controls.maxDistance`, brouillard et plan lointain suivent l'étendue. Échec du chargement : non fatal.
- Tuiles obsolètes : `ecrire_tout` écrit puis supprime les `T_*_*_*.glb` absents du nouvel index.
- Compatibilité : Python 3.8+ (pas de barre oblique inverse dans les expressions de f-strings). Pillow facultatif (couleurs moyennes) ; numpy non utilisé.

## Décisions de la v32 (22/10/2026) : zones dans une région en tuiles
- **Références d'objets** : `glb2tiles.py` écrit `extras.ref` et `extras.box` (boîte monde de l'objet ENTIER, identique dans chaque morceau réparti) sur chaque nœud copié ; `X.tiles.json` : `nodeRefs` 1 (0 avec `--sans-references`). Règle de la référence (même esprit que `resolveMeshRef`) : nom du nœud (sinon nom de son mesh) s'il est unique dans le GLB entier, sinon `nom#index` en pré-ordre ; calculée sur les noms du GLB, **pas** sur ceux de three.js (le GLTFLoader renomme les doublons `x_1`, retire `/ . espaces`). Les nœuds exclus comptent dans les rangs. Une zone liée écrite en mode tuiles ne s'utilise qu'en mode tuiles.
- **Coquille et viewer** (`core.js`) : `TL.refIndex` (ref -> nœuds des tuiles chargées, tenu par `refsAdd` / `refsRemove` à l'ajout et au retrait du groupe) ; `findMeshes` / `refBox` en mode tuiles lisent cet index et `userData.box` ; `zoneOff(z)` = zone liée sans tuile chargée : absente de `buildZones`, de `zoneTick` et des boucles de portails ; `relinkZones` (dans `tilesTick`) ne reconstruit que si `linkSignature` change. Les zones liées d'un `setZones` antérieur à la lecture de `X.tiles.json` sont gardées ; si les tuiles n'ont pas `nodeRefs` elles sont retirées avec l'avertissement « …redécouper avec glb2tiles v32 » (`tilesNoRefs`, texte testé par `tests/tuiles.py`).
- **Source de fichiers** : `loadTiles(rel, { source, force, target })` ; `source = { json(rel), buf(rel, signal) }` (chemins relatifs à la racine de la source ; défaut : `urlSource()`, http relatif à la page). `force` : le viewer ouvre une région sans champ `tiles` (`TL.on` est donc modifiable) ; `closeTiles()` libère tout et rétablit caméra, brouillard, `controls.maxDistance` (`BASE`). Le viewer fournit `fileSource(map)` pour un dossier choisi (`webkitdirectory`) ou glissé (`webkitGetAsEntry`, lecture par lots de `readEntries`), et `?tuiles=` (`safeRelV` = même règle que `safeRel`).
- **Viewer en mode tuiles** : repère d'origine, rotation forcée à 0 et désactivée, mer à 20 m, cible = centre de l'étendue (règle `tiles_default_target`), trou relatif à `viewer.seaCenter`, exports HTML / `.zip` désactivés, commande `--tiles` (`buildCommand`), `X.zones.json`. Clic hors tuile chargée : `viewer.overviewHit(ray)` puis `viewer.tilesForce(x, z)` (15 s) et message texte (`tileMiss`) ; jamais de pose sur la vue d'ensemble. Ouvrir un GLB ensuite : `leaveTiles()` -> `closeTiles()`.
- **Position affichée** : `#posInfo` dans le panneau d'aide de la coquille (cible ou avatar, 1 décimale) ; section « Coordonnées (m) » du viewer, boutons de copie. API de test : `viewer.getZoneState()`.
- **Tests** : `tests/tuiles.py` génère ses tuiles avec `--sans-references` (attentes inchangées : format v31 = zones liées ignorées). Le lancer de rayon ne touche que les faces avant : les GLB synthétiques de `tests/glbfab.py` ont un terrain à face avant vers +Y et des matériaux double face.

## Décisions de la v33 (22/10/2026) : démarrage, arrivée par défaut, vol, vues, chat, couleur, zones dans le dossier

Pas la grille de collision (142 ms de calcul pour 1 M de triangles à x1, 2 s à x10). Ne jamais remettre un délai fixe : l'**ancre** (`TL.anchor`) reste la référence jusqu'à `walkStart`, `releaseAnchor()`, ou un déplacement de la cible de plus de 1 m.
- **Ancre et ordre** : tuiles de l'ancre (`tilesAt`) démarrées **avant** la vue d'ensemble ; aucune autre tuile ne démarre tant qu'elles ne sont pas prêtes ou en échec (`anchorOpen`). Grilles : la tuile qui contient `prioPoint()` (téléport en attente > avatar > ancre) passe avant les autres, budget `GRID_MS_PRIO` 40 ms par image contre `GRID_MS` 6. `loadTiles` attend les tuiles de départ au plus `opts.waitMs` (15 s) ; ensuite la coquille continue et `walkStart` utilise `TL.pending`.
- **Jamais d'écran noir sans texte** : `#groundWait` (z-index 55, au-dessus du fondu) affiche « Chargement du sol… n/m tuile(s) prête(s) · N s » (`waitInfo`, clé de `tilesInfo` comprend les secondes) dès l'arrivée demandée, `bootEnd()` passe la main au suivi normal ; une erreur de chargement retire le fondu.
- **Journal par tuile** (`tileReady`, `tileFail`) : console `[tuile] …` et `tilesState().log` (octets, triangles, `startWaitMs`, `downloadMs`, `parseMs`, `queueMs`, `gridMs` = travail réel, `gridWallMs`, `totalMs`, `startAt`, `at`). À garder.
- **Arrivée par défaut** : clé de config `targetExplicit` (script : `tuple(a.target) != tuple(TARGET)` ou `TARGET_EXPLICIT` du script exporté par le viewer ou `targetExplicit` du fichier de réglages ; viewer : `targetExplicit()`). Une config **sans la clé** compte comme explicite (`keepTarget`) : comportement d'avant. `viewer.setHome({pos,yaw,forF})` ; `walkStart()` sans point utilise le home si `forF` et la cible n'a pas bougé (< 5 cm) ; `R` / `goTo` / `returnHome`. Lien `#spawn=` ou `#pos=` : cadrage et ancre sur l'arrivée demandée.
- **Clés de `cfg` ajoutées** (toujours écrites, script et viewer identiques) : `zoneMarker` (`discret`/`portee`/`aucun`), `showSpawns`, `fly`, `targetExplicit`. Bloc `# <<DEFAULTS>>` : `ZONE_MARKER`, `SHOW_SPAWNS`, `FLY_ENABLED`, `TARGET_EXPLICIT`.
- **Vol / vues** (`core.js`) : `W.fly`, `W.view` (`fps`/`tps`/`free`), `W.cam`; sol sous la caméra par `floorAt` (surface à moins de 1 m au-dessus, sinon à moins de 12 m : point enfoui) ; la grille de collision garde les murs solides en vol; en caméra libre, `toggleWalk` (F) rend la main à l'avatar. `E` ne déclenche plus les zones en vol.
- **Chat** (`template.html`) : saisie persistante, flèches via `viewer.holdKey`, enregistrement local (BOM UTF-8, lignes `jj/mm/aaaa hh:mm:ss | Nom | texte`, historique du serveur exclu), pseudo cité (`(?<![\p{L}\p{N}_])@?NOM(?![\p{L}\p{N}_])`, indicateurs gras + `@ `, `viewer.blinkBubble`, bip Web Audio après interaction), complétion `@` (5 pseudos au plus, insère `@Pseudo `). Réglages visiteur dans `localStorage` clé `glb2html_visitor` (`color`, `bold`, `blink`, `sound`).
- **Couleur** : `hello.color` (entier 0..0xFFFFFF) ; `presence_server.announced_color` rejette sans bruit tout le reste. Relancer le serveur pour en profiter.
- **Zones dans le dossier** (`viewer_tpl.html`, `saveZonesToDir`) : File System Access (poignée en mémoire + IndexedDB `glb2html_viewer`/`dirs`), `X.zones.bak.json` unique, dossier refusé s'il ne contient pas le fichier `X.tiles.json` ouvert, repli par téléchargement avec la phrase imposée. `glb2html.py --tiles --zones` = `X.zones.json` de destination : « zones déjà en place » (`zones_keep`).
- Le panneau d'aide `#walkHint` laisse passer les clics (`pointer-events:none`, sauf champs et boutons) : il est devenu plus haut et masquait le survol des marqueurs.
- Tests : `tests/tuiles.py` attend maintenant un texte qui **commence par** « Chargement du sol… » (règle 1c : tuiles prêtes et temps écoulé en plus).

## Livraison d'une version
À chaque nouvelle version :
1. Mettre à jour `VERSION` (format `vNN (jj/mm/aaaa)`).
2. Mettre à jour `CHANGELOG.md` (nouvelle section en tête, date jj/mm/aaaa).
3. Mettre à jour `HISTORIQUE.md` : une ligne de plus dans le tableau, avec la date jj/mm/aaaa, l'étiquette (`vNN`) et le contenu.
4. Fabriquer (`python build.py`) et lancer les tests avant de livrer.
5. Indiquer à JJ la commande pour poser l'étiquette Git, en PowerShell sur une seule ligne, par exemple : `git tag v20 <commit>; git push origin v20`.
